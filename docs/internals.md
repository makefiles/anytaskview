# anytaskview 내부 동작

사용법은 [README](../README.md), 설치는 [INSTALL](../INSTALL.md), 보안은 [SECURITY](../SECURITY.md) 에 있다. 여기에는 구조와 동작의 자세한 규칙을 적는다.

## 구성

| 자리 | 하는 일 |
|---|---|
| `.claude-plugin/` | 플러그인(`plugin.json`)과 이 저장소 하나로 된 마켓플레이스(`marketplace.json`) |
| `.mcp.json`, `hooks/hooks.json` | 플러그인이 등록하는 MCP 서버와 훅. 모두 `scripts/atv` 로 부른다 |
| `.codex-plugin/`, `.codex-mcp.json`, `hooks/codex.json` | Codex 플러그인(같은 저장소). 매니페스트가 훅·MCP 파일을 적어 Codex 는 `hooks/hooks.json` 을 읽지 않는다(읽으면 `args` 가 버려져 `atv` 가 인자 없이 돈다). MCP 는 `"cwd": "."` 이어야 플러그인 폴더 기준으로 풀린다(`${CLAUDE_PLUGIN_ROOT}`·`${PLUGIN_ROOT}` 는 MCP 명령에서 풀리지 않음, 0.163 실측). 훅 명령은 셸로 돌고 `$PLUGIN_ROOT` 를 받는다. 마켓플레이스는 Codex 도 `.claude-plugin/marketplace.json` 을 읽는다 |
| `skills/anytaskview/` | 그리기 자세한 안내(스킬). 늘 필요한 규칙은 MCP 안내문(`mcp/tools.js`)에 있다 |
| `scripts/atv` | 실행기. node 22.12 이상을 찾아 기억하고 훅·MCP·화판 서버를 실행한다(`ANYTASKVIEW_NODE` 로 정할 수 있다) |
| `scripts/board.js` | 화판 서버(127.0.0.1:4871). `--url` 은 처음 여는 브라우저에 쓸 주소, `--stop` 은 떠 있는 서버 멈추기 |
| `lib/scene.js` | 장면 모델. 명령·사실을 검사해 결과를 만들고 적용한다. 서버와 브라우저(재생)가 같이 쓴다 |
| `lib/server.js` | HTTP·SSE, 세션 짝짓기, 기록(JSONL) |
| `mcp/server.js` | stdio MCP 서버(SDK 없이 JSON-RPC 를 직접 쓴다). 화판 서버가 꺼져 있으면 떼어 내 띄운다 |
| `hook/hook.js` | Claude Code 훅. 사건을 짧은 사실로 줄여 보낸다(800ms 안, 언제나 0 으로 끝남). 예외: Stop 의 `--rewake` 는 화판 메시지를 최대 한 시간 기다렸다가, 받으면 stderr 로 내고 2 로 끝난다. 한 번 실행하고 끝나는 세션(`claude -p`·SDK: `CLAUDE_CODE_SESSION_ATTENDED=0` 이고 진입점이 `sdk-*`)에서는 기다리지 않는다(기다리는 동안 claude 가 답을 내고 끝나지 못한다). `claude --bg` 세션은 지켜보지 않음(0)이어도 진입점이 cli 라 기다린다 |
| `scripts/nudge` | 그리기 알림(sh, 동기 훅). 사용자 입력 뒤 도구를 8번 넘게 썼는데 그 대화의 화판에 그림이 없으면 그 대화에 한 번 알린다(`ANYTASKVIEW_NUDGE_AFTER` 로 횟수를 바꾼다). 도구마다 돌아서 node 를 띄우지 않는다. 파일은 Claude 면 claude 프로세스 번호(`CLAUDE_PID`), Codex(인자 `codex`)면 세션 id 로 가른다. Codex 는 하위 에이전트의 도구 사건에 agent_id 가 없어 주 대화와 함께 센다 |
| Codex 훅(`hook.js --codex`) | 세션 프로세스는 가장 가까운 `codex` 조상(물려받은 `CLAUDE_*` 는 보지 않음). SessionStart 는 화판과 통신하기 전에 그리기 규칙(MCP 안내문과 같은 글)을 출력한다(Codex 는 MCP 안내문을 모델에 넘기지 않고 SessionStart 출력은 developer 메시지로 넣는다). `apply_patch` 는 결과의 `Success. Updated the following files:` 아래 `A/M/D 경로` 줄마다 고친 파일로, 없으면 패치 머리의 경로로 「고치기 실패」 를 남긴다(5개까지). `PermissionRequest` 는 「입력 필요」. Bash 결과에는 종료 코드가 없어 실패도 「끝」 이다. Stop 에서 기다리지 않는다 |
| `web/` | 화면. `web/vendor/` 는 빌드된 브라우저 라이브러리(`npm run vendor` 로 다시 만든다) |

상태(열쇠, 세션 기록 `sessions/`, 프로젝트 정의·소속 `projects.json`, 큰 그림 기록 `projects/`, 설정 `config.json`, `board.log`, 고른 node 경로)는 저장소 밖 `~/.local/state/anytaskview/` 에 둔다(`ANYTASKVIEW_HOME` 으로 바꿀 수 있다). 플러그인을 갱신하거나 지워도 남는다.

## 화면에서 하는 일

- 세션 이름: 맨 위 이름을 눌러 바꾼다. 화판 이름 > Claude Code 이름(`/rename`, `claude -n`) > 첫 프롬프트 순서로 보인다.
- 프로젝트: 여러 대화에 걸친 일 하나다(07 판까지의 「묶음」 을 옮겨 왔다. 새 판이 처음 뜰 때 `groups.json` 을 `projects.json` 으로 옮기고 옛 파일은 남긴다). 프로젝트마다 큰 그림 화판(`projects/<id>.jsonl`, 세션 기록과 같은 형식)이 있어, 프로젝트에 든 대화의 Claude 가 `plan`·`draw`·`note` 에 `project` 를 붙여 작업 단위를 시작·끝낼 때와 결정 때 고친다. 서버는 그 대화의 지금 소속과 같을 때만 받고, 큰 그림에는 `clear` 를 받지 않으며, 부품·단계마다 마지막으로 쓴 대화(`by`)와 기록 번호(`at`)를 남긴다. 대화가 큰 그림을 본 번호(프로젝트 안내·`ids` 를 받은 때, 메모리에만 두며 다시 띄우면 읽은 때부터)보다 뒤에 다른 대화가 바꾼 부품·단계를 고치거나 지우면, 쓰기는 하고 결과에 「다른 대화가 바꾼 것을 덮었습니다」 를 붙인다. 목록에서 프로젝트 이름을 누르면 큰 그림과 「대화 이력」(대화마다 시작 시각·상태·고친 파일 수·올린 계획의 끝난 단계, 큰 그림의 메모)이 보인다. 진행률은 내지 않는다(계획을 올리지 않은 대화가 있다).
- 대화가 프로젝트에 드는 길(앞선 쪽이 이긴다): 사용자가 끌어 놓기·⋯ 메뉴(「프로젝트 없음」 에 놓으면 「뺌」 으로 남아 자동으로 다시 넣지 않는다) > 이어받기 문구(아래) > Claude 판단(세션 시작 때 SessionStart 훅이 후보를 5개까지 맥락에 넣고, Claude 가 `project` 도구로 들어간다. 같은 저장소·브랜치에서 쓰인 프로젝트가 앞에 오지만 경로만으로 넣지는 않는다) > `/clear`·fork·이어받기로 이어진 대화의 물려받기(끝난 프로젝트는 물려받지 않는다. 사용자가 뺀 줄은 `/clear`·fork 로 이어진 대화도 뺀 채로 두고, 이어받기 문구로 이어진 대화에는 물려주지 않는다). 이어받기 문구의 키를 가진 프로젝트가 없으면 앞 대화에서 물려받은 프로젝트에 그 키를 붙인다. 인계 문서를 고친 대화는 아무 프로젝트도 갖지 않은 키만 자기 프로젝트에 붙인다. 어느 것도 아니면 「프로젝트 없음」 이다. 소속이 바뀌면(문구·사용자) 그 대화의 다음 도구 결과에 한 번 알린다. 알림과 `project` 도구의 답에는 큰 그림의 이름표와 아직 답을 받지 않은 결정 대기·막힘 메모 글(최근 셋)이 실린다. 큰 그림에 쓰는 호출은 쓸 차례가 왔을 때 소속을 다시 보고, 그사이 사용자가 옮겼으면 거부한다. 이어받기 키가 있는 대화를 다른 프로젝트로 옮기면 키도 옮겨 간다.
- 이어받기 문구(설정, 기본 꺼짐): 맨 위 「설정」 에서 첫 입력 문구(예: `이어서 <키>`, `<키>` 뒤에 글을 두면 그 글까지 맞아야 한다)와 인계 문서 경로(예: `/handoff/<키>.md`)를 정한다. 첫 입력이 그 문구면 그 키를 가진 앞 대화에 잇고 그 키의 프로젝트에 넣는다(처음 보는 키는 그 이름으로 새 프로젝트). 07 판까지는 이 규칙이 코드에 박혀 있었으므로, 새 판이 처음 뜰 때 옛 기록에 인계 키가 있으면 그 규칙을 설정에 넣는다.
- 지우기: 줄의 ⋯ 메뉴 「지우기」 를 두 번 누르면 그 줄의 끝난 대화(숨긴 빈 대화 포함)를 지운다. 진행 중인 대화는 남는다. 서버(`sess-delete`)는 기록 파일을 상태 폴더의 `trash/<세션>.<지운 시각>.jsonl` 로 옮기고 프로젝트 소속을 지운 뒤 SSE `drop` 으로 알린다. 30일이 지난 것은 서버가 뜰 때와 한 시간마다 비운다. 되살리려면 그 파일을 `sessions/<세션>.jsonl` 로 되돌려 놓고 화판 서버를 다시 띄운다(같은 이름의 새 기록이 생겼으면 덮어쓰지 않는다). 같은 세션 id 로 사건이 다시 오면(`claude --continue`) 새 기록으로 시작한다.
- 이어진 대화: `/clear`·fork(같은 claude 의 직전 세션)와 첫 입력이 이어받기 문구인 세션(그 키로 이어받았거나 인계 문서를 고친 가장 최근 세션)은 세션 메타의 `prev` 로 잇는다. 목록에는 한 줄로 보이고 맨 위 ◀ ▶ 로 앞뒤 대화를 본다. 그림은 대화마다 따로다. resume·continue 는 같은 세션 id 라 그대로 이어진다.
- 입력도 그림도 없이 끝난 세션(CLI 명령이 잠깐 띄운 MCP·훅)은 목록에서 숨긴다. 모르는 세션의 SessionEnd 만으로는 세션을 만들지 않는다.
- 배치: 후보 여섯 개를 재 보고 고른다. 그림 전체를 한 방향으로 놓는 넷(LLM 이 준 방향·반대 방향, 각각 줄 바꿈 `elk.layered.wrapping` 없음·있음)과, 바깥과 묶음 안의 방향을 다르게 놓는 「섞기」 둘(`SEPARATE_CHILDREN`, 선이 없는 층은 `rectpacking` 으로 채워 넣음)이다. 고르는 순서는 다 들어가는 배율(100% 상한, 3% 안쪽은 같음) → 줄 바꿈하지 않은 것 → 직접 그린 선이 다른 상자를 덜 지나는 것 → 가로:세로가 칸에 가까운 것이다. 섞기에서 ELK 는 묶음 경계를 넘는 선의 경로를 내지 않으므로, 그 선은 배치에만 조상끼리 이어 넣고 화면에는 직접 그린다. 직선(두 상자 가운데를 이음), ㄱ자 둘, ㄹ자 둘(두 상자 사이 틈의 가운데에서 꺾음) 가운데 다른 상자를 덜 지나는 것, 같으면 덜 꺾인 것, 그다음 짧은 것을 그린다. 후보가 모두 지나면 상자들을 8px 넓힌 장애물로 두고 그 테두리 좌표의 격자에서 꺾임(40px 로 침)과 길이가 가장 적은 돌아가는 길을 찾는다(`web/route.js`, 길이 없으면 덜 지나는 후보). 구조가 바뀔 때만 다시 고르고 창 크기만 바뀌면 그대로 둔다. 배치를 재는 동안 구조가 같은 사건이 오면 재던 배치를 이어 가고(새로 시작하지 않는다), 그동안은 따라가기를 하지 않는다.
- 연결: 화면은 문서를 떠날 때(pagehide) SSE 를 닫고, 뒤로 가기 캐시에서 돌아오면 다시 잇는다. 닫지 않으면 옛 문서가 연결을 쥔 채 남아 같은 탭에서 다섯 번쯤 새로 열면 화판이 뜨지 않았다. 브라우저는 한 호스트에 연결을 6개까지 쓰므로, 화판 탭·타임라인 새 창은 SharedWorker(`web/hub.js`)의 SSE 하나를 나눠 쓴다. worker 는 `/events?chan=<무작위>` 를 열고, 탭들이 보는 세션 id 를 모아 `POST /api/sub`(읽기 쿠키, 같은 Origin)로 알린다. 서버는 새로 받는 세션과 `fresh` 에 든 세션의 스냅샷을 같은 연결로 보내고, worker 는 그 스냅샷을 기다리던 탭에만 넘긴다(연결 하나의 사건은 순서대로 오므로 스냅샷 뒤의 변경만 넘기면 빠짐이 없다). `res` 에는 세션 id 가 실리고, 아직 화판이 없는 프로젝트는 빈 스냅샷(seq 0)을 받는다. 구독 요청만 실패하면 늦춰 다시 보내고, 연결이 아주 닫히면(다시 이을 때 401 따위) 새로 만든다. worker 는 탭이 하나라도 열려 있으면 살아 있으므로 `hub.js`·`/api/sub` 의 약속을 바꾸면 `web/app.js` 의 `HUB_VERSION` 을 올린다(주소가 달라 새 worker 가 뜬다). SharedWorker 가 없거나 뜨지 않으면 탭마다 `/events?session=` 으로 잇는다. 상자의 ref 는 파일 이름:줄만 보인다.
- 도움말: 맨 위 「도움말」 이나 `?` 키.
- Claude 에 보내기: 보내기 창 하나를 가리킨 자리에 띄운다. 그림의 상자·계획의 단계는 마우스를 올리거나 초점을 두면 뜨는 「보내기」(또는 초점에서 Enter)로 그 대상에, 세션 줄 ⋯ 「메시지 보내기…」 로 보던 화면을 바꾸지 않고 그 세션에, 맨 위 「Claude 에 보내기」 로 보는 세션 전체에 보낸다. 서버 `send` 가 요청의 `sid` 로 받는 세션을 정하므로 다른 세션에 보내기도 화면만 바꿨다. Enter 로 보내고 Shift+Enter 로 줄을 바꾸며, 한글 조합 중의 Enter 는 보내지 않는다. 쓰다 둔 글(초안)과 모은 글은 localStorage `atv.compose` 하나에 두어 탭·브라우저를 닫아도 남고 모든 탭이 같이 본다(주소가 같을 때만: `localhost` 와 `127.0.0.1` 은 따로). 초안은 받는 곳(세션·대상)마다 쓰는 동안 0.3초 뒤 저장하고 최근 50개까지 둔다. 바꿀 때는 Web Lock 안에서 최신값을 읽어 고치고, 다른 탭은 `storage` 사건으로 다시 읽는다(열린 보내기 창의 글은 덮지 않는다). 글마다 `cid` 를 붙여 보내고, 서버는 같은 세션에 같은 `cid` 가 있으면 내용이 같을 때 「이미 받음」 으로 성공을 돌려주고 다르면 거절한다(보내는 사이 탭이 닫혀 다시 보내도 한 번만 들어간다). 저장이 안 되면 띠와 보내기 창에 알린다. 쉬는 세션은 깨우고, 일하는 중이면 그 차례 안에서 받는다(플러그인으로 설치한 세션). 30분 안에 못 보내면 만료된다. 보내기 창의 「모아 두기」 로 한 세션에 보낼 글을 모았다가 화면 아래 띠에서 한꺼번에 보낸다. 서버 `send` 는 `items`(1~20개)를 받으면 이미 받은 `cid` 는 건너뛰고 새 글은 기록 한 줄에 모두 넣거나 하나도 넣지 않는다(대기 20개 한도는 이미 대기 중인 글과 새 글을 합쳐 센다). 받을 대화가 끝났거나 지워졌으면 띠에 그렇게 보이고 보내기를 끈다(모은 글은 사용자가 빼거나 비울 때까지 둔다). 글을 보낸 상자·단계에는 보낸 글 수 ✉N 이 붙고(대기 중인 글이 있으면 대기 색), 누르면 그 대상의 보내기 창이 열린다.
- Codex 세션: SessionStart 의 `via: "codex"` 로 알고 목록 줄과 맨 위 이름 앞에 Codex 로고를 붙인다(Claude 세션은 Claude 로고, 화면 읽기 프로그램에는 이름). MCP 호출은 Codex 가 `_meta["x-codex-turn-metadata"].session_id` 로 싣는 세션 id 를 짝짓기 표보다 앞세운다(데스크톱 앱·VS Code 의 app-server 는 한 프로세스에 세션이 여럿이고 세션마다 MCP 프로세스가 따로 뜬다). 세션을 띄운 프로세스의 명령줄에 `app-server` 가 있으면 `shared` 로 두고, 같은 pid 의 다른 세션을 앞 대화로 잇지 않는다. MCP 의 hello 는 initialize 뒤에 보내고, Codex 클라이언트(`codex-mcp-client`)면 아는 세션 id(`ANYTASKVIEW_SESSION`)가 있을 때만 짝짓는다(다른 클라이언트는 예전처럼 이 프로세스의 id 로). 보내기는 화판 서버가 `codex queue --thread <세션> --message <글>` 을 세션마다 하나씩 부른다(셸 없음, 실행 파일은 그 세션의 `/proc/<pid>/exe` 가 이름이 codex 일 때, 아니면 `PATH`, `CODEX_HOME` 은 훅이 알려 준 값). 큐에 넣은 뒤에만 「보냄」 으로 기록하고(그 기록이 실패해도 큐에 넣은 글은 메모리에 두어 다시 보내지 않는다), 분명한 실패는 대기로 두고 이유(`qerr`)를 보이며 다음 보내기·그 세션의 차례 끝·세션 시작 때 다시 한다. 20초 안에 답이 없으면 프로세스 묶음째 죽이고(PATH 의 codex 는 npm 래퍼라 진짜 codex 가 손자다) 들어갔는지 모르므로 「전달 확인 못 함」(`unsure`)으로 만료한다. `unsure` 글은 같은 글 번호(cid)로 다시 보내면 「이미 받음」 이 된다. Codex 훅은 모든 사실에 `via`·`home`(없으면 `~/.codex`)을 싣고, SessionStart 를 받지 못한 세션(그때 화판이 아직 뜨지 않음)은 다른 사실로 Codex 메타와 짝짓기를 채운다. 시작할 때마다 `shared`·`home`·`bin` 을 덮어써 다른 화면에서 이어 연 세션에 옛 값이 남지 않는다. 받을 수 있는 세션은 끝나지 않았고 그 codex 의 지금 세션(`/clear` 앞 세션 제외)이거나 `shared` 인 것이다.
- 패널 폭·접기·그림 배율·타임라인 거르기는 이 브라우저에 기억한다. 타임라인은 「새 창」 으로 떼어 볼 수 있다.
